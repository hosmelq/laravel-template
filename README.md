# Laravel Template

Laravel Template is a starting point for Laravel applications with PostgreSQL, Sentry, strict development tooling, and optional features installed through an interactive command.

## Introduction

The base application includes the dependencies and conventions used by every project: PostgreSQL, Octane, Sentry, Resend, audit logs, production configuration validation, a Filament admin panel at `/admin` for the emails listed in `ADMIN_EMAILS`, and strict development tooling. Application-specific features are kept in patches and can be installed together in any combination.

## Requirements

- Composer
- Docker
- Git
- Mise 2026.9.15 or newer

## Installation

First, create a new repository from this template and clone it locally.

Next, trust the project configuration and install its system packages and development tools:

```bash
mise trust
mise bootstrap
```

After that, install the base application:

```bash
mise run setup
```

This prepares the environment files, starts the local Docker services (PostgreSQL and Mailpit), writes their ports to `.env` and `.env.testing`, and runs the migrations.

Use `mise run setup:ci` to install and prepare the application without running migrations or installing agent configuration. When frontend is installed, this also builds its assets.

Finally, run the interactive installer and select the features required by the application:

```bash
php artisan template:install
php artisan migrate
```

## Optional Features

The installer currently provides:

- **Authentication** — Laravel Fortify login, registration, password reset, email verification, and two-factor authentication, with audit logs for sign-in events. With Frontend, it also adds the authentication pages.
- **Frontend** — Inertia with server-side rendering, React, HeroUI and HeroUI Pro, Font Awesome Pro, Tailwind CSS, Vite, PostHog, Portless development URLs, and frontend tooling.
- **Health** — Application health checks, the health endpoint, the admin-only health results page, scheduled checks, and Slack alerts when `HEALTH_SLACK_WEBHOOK_URL` is set.
- **Media** — Media Library, image processing, and S3 filesystem support.
- **Organizations** — Organizations, memberships, ownership, per-organization Owner, Admin, and Viewer roles, permissions, policies, invitations, and current-organization support. With Frontend, it also adds the organization layout, settings, creation, and invitation pages.
- **Railway** — Railway infrastructure as code in `.railway/railway.ts` (its SDK lives in `.railway/package.json`) and Docker images for the app, queue, and scheduler services. Deployments wait for CI on `main`. With Frontend, the app image builds the assets and an `ssr` service runs the Inertia SSR server.

Selected patches are checked and applied as a single group. Combination patches, named after the features they join in alphabetical order (for example `authentication+frontend.patch` or `authentication+frontend+organizations.patch`), are then applied when every feature they need is selected, one pass per combination size. The installer then updates Composer dependencies, installs and builds the frontend when selected, installs the Railway SDK in `.railway` when selected, and runs `mise run setup:agent`.

Generated files such as `composer.lock`, `nub.lock`, and agent configuration are not stored in the patches; they are regenerated by their respective installation commands.

Features that are already installed are skipped.

After a successful installation, the installer command, patches, related tests, and feature-combination script are removed. Select every feature the application needs during the initial run.

## Private Packages

The frontend installs HeroUI Pro and Font Awesome Pro, which need credentials:

- **Locally**, Mise loads `HEROUI_AUTH_TOKEN` from `~/.config/template/env` and points npm to `~/.config/template/npmrc`, which holds `//npm.fontawesome.com/:_authToken=<token>`. Rename `template` in the `[env]` section of `mise.toml` to match the application.
- **In GitHub Actions**, create a `package-registries` environment with the `FONTAWESOME_NPM_AUTH_TOKEN` and `HEROUI_AUTH_TOKEN` secrets. Renovate reads `FONTAWESOME_NPM_AUTH_TOKEN` from its own secrets.
- **On Railway**, set both variables on the `app` and `ssr` services; the images receive them as build arguments.

## Development

Start the local Docker services, queue worker, scheduler, logs, and—when the frontend feature is installed—the Octane server and Vite behind Portless URLs with:

```bash
mise run dev
```

Stop the Docker services with `mise run services:stop`, or remove them and their data with `mise run services:destroy`.

Create a production build with:

```bash
nub run build
```

## Checks and CI

CI runs on `main` only. Before each push, Lefthook runs `mise run push:check` (tests, PHPStan, Pint, and Rector). To sign off a pull request, run the same checks as CI locally with:

```bash
mise run signoff
```

When CI fails on `main`, a Pullfrog run investigates and opens a draft fix. Every merge to `main` also gets an automated Pullfrog review.

## Testing

Start the local services and run the test suite with:

```bash
mise run services:start
vendor/bin/pest
```

Test every optional feature combination in an isolated temporary checkout with:

```bash
scripts/test-template-feature-combinations
```

## Deployment

With Railway installed, replace the `template/template` repository and `Template` project names in `.railway/railway.ts`. The images decrypt `.env.<APP_ENV>.encrypted` on start and validate the production configuration, so commit the encrypted environment file and set `APP_ENV` and `LARAVEL_ENV_ENCRYPTION_KEY` on each Railway service:

```bash
php artisan env:encrypt --env=production
```

Preview and apply the infrastructure from the directory linked to the Railway project:

```bash
railway config plan
railway config apply
```
